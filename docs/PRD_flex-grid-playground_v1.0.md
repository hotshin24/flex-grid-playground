## 2. 목표



### 2.1 학습 목표 (1순위)

이 프로젝트의 목적은 산출물 자체가 아니라 **제작 과정에서의 개념 체득**이다.

1. CSS Grid 속성 19개를 값 단위로 직접 조작하며 동작 원리 체득
2. Flex와 Grid의 **개념 대응 관계**를 구조적으로 정리 (`justify-content`가 두 모델에서 다르게 동작하는 지점 등)
3. 스키마 주도 UI 생성 패턴 구현 — 데이터로 UI를 만드는 사고방식 습득
4. 상태 관리 · 렌더링 분리 · 이벤트 위임 등 프레임워크 없이 구현하며 원리 이해



### 2.2 산출물 목표

Flex와 Grid를 **동일한 4탭 구조로 풀 패리티** 제공하는 정적 학습 사이트.

### 2.3 Non-goals


| 제외 항목                     | 사유                         |
| ------------------------- | -------------------------- |
| 빌드 도구 (Vite, webpack 등)   | 무의존성 원칙 유지 — 파일을 열면 곧바로 동작 |
| 프레임워크 (React 등)           | 원리 학습이 목적이므로 추상화 계층 배제     |
| 백엔드 · 계정 · 로그인            | 정적 사이트 범위 유지               |
| 다국어                       | 한국어 단일                     |
| Subgrid · Container Query | v1.0 범위 밖 (v1.1 후보)        |

## 4. 아키텍처



### 4.1 설계 원칙

**속성 스키마가 단일 진실 공급원(Single Source of Truth)이다.**

컨트롤 UI, 코드 생성기, 챌린지 정답 검증, 속성 설명 데모가 모두 하나의 스키마 정의에서 파생된다. 새 속성 추가 = 스키마 항목 추가.

### 4.3 속성 스키마 규격

```js
{
  prop: 'justify-content',        // CSS 속성명
  jsProp: 'justifyContent',       // DOM style 키
  scope: 'container',             // 'container' | 'item'
  control: 'enum',                // 컨트롤 타입 (아래 표 참조)
  default: 'flex-start',
  values: [...],                  // control === 'enum'일 때
  desc: '...',                    // 속성 설명
  tip: '...',                     // 학습 팁
  axisAware: true,                // 주축 방향에 따라 결과가 달라지는가
  demo: { ... },                  // 속성 설명 탭 데모 설정
  inactiveWhen: {                 // 유형 A. 이 조건이 참이면 효과 없음
    prop: 'flex-wrap',            // 판정 대상이 되는 다른 속성의 jsProp
    equals: 'nowrap',             // equals | notEquals | in 중 하나
    reason: 'flex-wrap이 nowrap이라 줄이 하나뿐입니다',
    hint: 'flex-wrap을 wrap으로 바꿔보세요'   // 선택
  },
  measuredInactive: {              // 유형 B·C. 속성 단위 조건
    key:    'hasFreeSpace',        // MEASURED_KEYS 의 키. 참이어야 속성이 일한다
    reason: '...',                 // 거짓일 때 표시할 사유 (F-13-3)
    hint:   '...'                  // 해결 방법 (F-13-5). 유형 C 는 필수
  }

  // 값 단위 조건은 values[] 안에 선언한다.
  // 속성 전체가 아니라 특정 값에서만 조건부인 경우에 쓴다.
  values: [
    { val: 'stretch', desc: '...', measuredInactive: { key, reason, hint } },
  ]
}
```

> `inactiveWhen`과 `measuredInactive`는 모두 선택 필드다. 없으면 항상 활성으로
> 간주한다.
>
> `measuredInactive.key`가 참조하는 측정 키의 목록(`MEASURED_KEYS`)과 판정 로직은
> `renderer.js`가 소유하며, 스키마는 키 이름만 선언한다. 스키마가 렌더링 세부를
> 알아서는 안 된다. `MEASURED_KEYS`에 없는 이름은 `validateSchema`가 잡는다.
>
> 속성 단위 선언은 컨트롤 전체를, 값 단위 선언은 해당 값 버튼 하나만 비활성으로
> 표시한다. 값 단위 선언이 있어도 속성 자체의 판정에는 끼어들지 않는다
> (`aria-disabled="false"` 유지).

**컨트롤 타입 정의**


| 타입           | 용도             | 사용 속성 예                             |
| ------------ | -------------- | ----------------------------------- |
| `enum`       | 고정 값 버튼 그룹     | `flex-direction`, `justify-content` |
| `number`     | 정수 슬라이더        | `flex-grow`, `order`                |
| `length`     | 수치 + 단위 선택     | `gap`, `flex-basis`                 |
| `track-list` | 트랙 추가/삭제/단위 편집 | `grid-template-columns/rows`        |
| `area-grid`  | 셀 매트릭스 시각 편집   | `grid-template-areas`               |
| `span`       | 시작/끝 라인 좌표 입력  | `grid-column`, `grid-row`           |


> `track-list` · `area-grid` · `span` 3종이 Grid를 위해 신규 도입되는 컨트롤이며, 이것이 v0.1 구조로 확장이 불가능했던 직접적 원인이다.



### 4.4 상태 모델

```js
{
  topic: 'flex' | 'grid',
  tab: 'playground' | 'explain' | 'examples' | 'challenge',
  container: { /* 토픽별 스키마의 container 속성 */ },
  items: [ { id, ...토픽별 item 속성, width, height } ],
  selectedId: Number,
  view: {                    // 도구 뷰 설정. 스키마 속성이 아니며 코드 생성 대상 아님
    containerWidth: Number | null,   // null = components.css 기본값 사용
    containerHeight: Number | null,  // null = components.css 기본값 사용
  },
  measured: {                    // renderer가 렌더 후 기록. 유형 B·C 판정 근거
    lineCount: Number,           // 실제 줄 수
    hasFreeSpace: Boolean,       // 주축(Flex) · 인라인축(Grid)에 남는 공간
    hasCrossFreeSpace: Boolean,  // 교차축 · 블록축에 남는 공간
    isOverflowing: Boolean,      // 아이템이 컨테이너를 넘쳤는가
    shrinkBlocked: Boolean,      // min-* 하한에 막혀 더 줄지 못하는가
    canShrink: Boolean,          // 줄어들 여지가 실제로 있는가
    crossAuto: Boolean,          // 아이템에 교차축 크기가 지정되지 않았는가
    hasImplicitColumns: Boolean, // 암시적 열이 생성됐는가
    hasImplicitRows: Boolean,    // 암시적 행이 생성됐는가
    hasPlacementGaps: Boolean,   // 배치되지 않은 빈 칸이 있는가 (dense 판정용)
  }
}
```

> 목록은 `schema-spec.js`의 `MEASURED_KEYS`가 기준이다. 키가 늘면 여기도 갱신한다.
> 두 곳이 어긋나면 `validateSchema`가 잡지 못하는 선언이 생긴다.

- 토픽 전환 시 상태는 토픽별로 **독립 보존** (Flex에서 만든 설정이 Grid 전환 후 복귀해도 남아 있음)
- Undo/Redo 히스토리는 토픽별 스택으로 분리
- `view`는 도구 설정이므로 `codegen.js`의 출력 대상에서 제외한다. Undo/Redo 히스토리
  포함 여부는 구현 시 판단한다.
- `measured`는 `renderer.js`만 쓴다. 사용자 조작으로 변경되지 않으며 Undo/Redo와
  URL 직렬화 대상이 아니다. `codegen.js` 출력에도 포함하지 않는다.
- `measured` 갱신이 다시 렌더를 유발하지 않도록 주의한다. 무한 루프 위험이 있다.



### 4.5 URL 직렬화

```
#/grid/playground?tc=1fr+1fr+1fr&rg=20px&n=6&ice.2=span+2&sel=2
```

- 해시만 사용 (정적 호스팅 호환)
- 파라미터는 스키마 정의 순서를 따르는 축약 키(`urlKey`)
- 아이템 속성은 `urlKey.<아이템 id>`. 스키마 밖의 값은 예약 키를 쓴다 —
  `n`(아이템 수) · `sel`(고른 아이템) · `iw`·`ih`(아이템 크기)
- 기본값과 동일한 속성은 URL에서 생략
- 값은 `CONTROL_TYPES`의 `serialize`가 적고 `parse`가 읽는다. 인코딩은
  `URLSearchParams`에 맡긴다 (공백은 `+`, 줄바꿈은 `%0A`)
- 파싱 실패 시 기본 상태로 폴백하고 경고 없이 진행
- `view`·`measured`는 담지 않는다 (4.4)

> **트랙 목록은 펼쳐 적는다.** v1.3까지 이 자리의 예시가
> `tc=repeat(3,1fr)`이었으나 `parseTrackList`는 `repeat()`를 읽지 못한다.
> 읽지 못하는 데다 오류도 내지 않아 트랙이 조용히 사라진다. 축약은 `codegen`이
> 출력할 때 판단하는 표기이고, URL은 상태를 그대로 옮기는 자리다.

> **주소는 `replaceState`로 쓴다.** 슬라이더가 `input`마다 상태를 바꾸므로
> `pushState`면 드래그 한 번이 히스토리 수십 칸을 만든다. 되돌리기는 이 도구의
> undo가 맡고, 주소창은 공유용 주소만 담는다. 부수로 순환도 끊긴다 —
> `replaceState`는 `hashchange`를 일으키지 않는다.

> **F-06 보충.** 너비와 높이를 모두 조절할 수 있어야 한다. `flex-direction: column`에서는
> 주축이 세로이므로, 높이가 고정되지 않으면 `flex-wrap`과 `align-content`의 동작을
> 관찰할 수 없다. Grid의 `align-content`·`grid-auto-rows`도 같은 조건을 요구한다.
>
> 컨테이너 크기는 **학습 대상 CSS 속성이 아니라 도구의 뷰 설정**이다. 토픽 스키마
> (`flex/schema.js` · `grid/schema.js`)에 항목으로 추가하지 않는다. 스키마에 넣으면
> `codegen.js`가 생성하는 사용자 CSS에 `width: 400px` 같은 도구 설정이 섞여 나온다.
>
> 조절 UI가 없거나 사용자가 값을 바꾸지 않은 초기 상태에서는 `components.css`가
> 제공하는 반응형 기본 높이가 적용된다. 사용자 지정값은 그 위에 덮어쓴다.

### 5.4 Flex ↔ Grid 개념 대조 (GR-09, P2)

동일 이름 속성이 두 모델에서 다르게 동작하는 지점을 나란히 비교하는 뷰.


| 속성                | Flex 기준               | Grid 기준                          |
| ----------------- | --------------------- | -------------------------------- |
| `justify-content` | 주축(방향 가변) 정렬          | 인라인축(가로) 트랙 전체 정렬                |
| `align-items`     | 교차축 정렬                | 블록축(세로) 셀 내부 정렬                  |
| `gap`             | 아이템 사이 간격             | 트랙 사이 간격                         |
| `order`           | 시각 순서 변경              | 동일 (auto-placement에 영향)          |
| —                 | `flex-basis` (1차원 크기) | `grid-template-columns` (2차원 트랙) |


### 5.5 조건부 속성 비활성 표시 (F-13, P1)

조건이 맞지 않아 효과가 나타나지 않는 속성을 화면에서 구분한다.

#### 대상 속성 목록

**Flex (5건)**

| 속성                     | 조건                          | 안 맞을 때 | 유형 |
| ---------------------- | --------------------------- | ------ | -- |
| `align-content`        | `flex-wrap ≠ nowrap`        | 완전 무시  | A  |
| `align-items: stretch` | 아이템에 교차축 크기 없음              | 효과 없음  | C  |
| `flex-shrink`          | 공간 부족 + `min-*` 하한 미도달      | 효과 없음  | C  |
| `flex-grow`            | 남는 공간 존재                    | 효과 없음  | B  |
| `order`                | 아이템 2개 이상                   | 효과 없음  | A  |

**Grid (7건)**

| 속성                            | 조건                                   | 안 맞을 때    | 유형 |
| ----------------------------- | ------------------------------------ | --------- | -- |
| `justify-content`             | 트랙 합계 < 컨테이너 너비 (`fr` 있으면 불가)        | 효과 없음     | B  |
| `align-content`               | 트랙 합계 < 컨테이너 높이                      | 효과 없음     | B  |
| `grid-auto-columns`           | 암시적 열 생성 조건 성립                       | 효과 없음     | B  |
| `grid-auto-rows`              | 암시적 행 생성 조건 성립                       | 효과 없음     | B  |
| `grid-area`                   | `grid-template-areas`에 해당 이름 존재      | 무시        | A  |
| `dense`                       | 배치되지 않은 빈 칸 존재                       | 효과 없음     | B  |
| `justify-self` / `align-self` | 부모 `justify-items`/`align-items`와 다름 | 시각적 변화 없음 | A  |

> 이 목록은 현재까지 파악된 것이다. 구현 중 추가로 발견되면 여기에 더하고,
> 6장 품질 기준의 건수를 함께 갱신한다. 두 곳의 숫자가 어긋나면 안 된다.

#### 판정 유형

| 유형 | 판정 근거      | 판정 주체                | 구현 시점 |
| -- | ---------- | -------------------- | ----- |
| A  | 다른 속성의 값   | `controls.js` (스키마 선언) | M2    |
| B  | 렌더 결과의 치수  | `renderer.js` (측정)     | M3    |
| C  | CSS 초기값 충돌 | `renderer.js` (측정) + 해법 안내 | M3    |

> 유형 B·C 는 속성 단위와 값 단위 두 방식으로 선언한다. 대상 속성 목록에
> `align-items: stretch` · `dense` 처럼 **값으로 적힌 항목**은 값 단위 선언이다.
> `dense`는 `grid-auto-flow`의 `row dense` · `column dense` 두 값에 걸리므로
> 선언 수는 대상 건수보다 많다. 위 목록의 한 행이 두 속성을 가리키는 자리도 있다
> (`justify-self / align-self`).
>
> 현재 상태 — 위 목록 **행 12건** = 대상 속성 **13건** = 선언 **14개**
>
> | 구분 | 수 | 내역 |
> |---|---:|---|
> | 유형 A (`inactiveWhen`) | 5 | Flex `align-content` · `order` / Grid `grid-area` · `justify-self` · `align-self` |
> | 유형 B·C 속성 단위 | 6 | Flex `flex-grow` · `flex-shrink` / Grid `justify-content` · `align-content` · `grid-auto-columns` · `grid-auto-rows` |
> | 유형 B·C 값 단위 | 3 | Flex `align-items: stretch` / Grid `dense` 2값 |
>
> 6장 품질 기준의 "12건" 은 **행 단위**이며 위 표와 정합한다.
> 세 곳(위 목록 · 이 각주 · 6장)의 숫자가 어긋나면 안 된다.

#### 요구사항

| ID     | 내용                                                        |
| ------ | --------------------------------------------------------- |
| F-13-1 | 유형 A는 스키마의 `inactiveWhen` 필드로 선언한다. 코드에 속성명을 하드코딩하지 않는다 |
| F-13-2 | 비활성 상태의 컨트롤은 시각적으로 구분된다. 단, **조작은 계속 가능해야 한다**        |
| F-13-3 | 비활성 사유를 문장으로 표시한다. 사유 문구는 스키마에 담는다                     |
| F-13-4 | 유형 B·C는 `renderer.js`가 렌더 후 측정 결과를 상태로 올린다               |
| F-13-5 | 유형 C는 사유와 함께 해법을 제시한다 (예: `min-height: 0`)                |
| F-13-6 | 넘침·잘림 등 비정상 렌더 상태를 프리뷰에 표시한다                             |

#### 설계 원칙

**비활성은 잠금이 아니다.** 컨트롤을 `disabled`로 막으면 학습자는 "왜 안 눌리지"에서
멈춘다. 눌러보고 아무 일도 안 일어나는 것을 직접 확인한 뒤 사유를 읽는 흐름이어야
개념이 남는다. `aria-disabled`로 상태만 알리고 `disabled` 속성은 쓰지 않는다.

**넘침을 숨기지 않는다.** 아이템이 컨테이너를 벗어나는 것은 가려야 할 결함이 아니라
가르쳐야 할 현상이다. `overflow: hidden`으로 잘라내지 않고, 넘쳤다는 사실을
표시한다.

**해법을 실험 가능하게 제공한다.** 유형 C는 사유 설명에 그치지 않고, 해당 CSS 초기값을
토글로 바꿔볼 수 있게 한다. `min-height: auto ↔ 0`을 직접 켜고 끄며 차이를 보는 것이
이 개념을 익히는 가장 짧은 경로다.
