# Flex & Grid Playground

CSS Flexbox와 Grid를 **값 단위로 직접 조작하며** 익히는 학습 도구입니다.
속성을 바꾸면 프리뷰가 바로 움직이고, 그 상태를 만드는 CSS·HTML이 함께 나옵니다.

**[살펴보기 →](https://hotshin24.github.io/flex-grid-playground/)**

빌드 도구도 의존성도 없습니다. 파일을 열면 그대로 동작합니다.

## 네 개의 탭

| 탭 | 하는 일 |
| --- | --- |
| **플레이그라운드** | 컨테이너·아이템 속성을 조작하고 결과를 본다. 생성된 CSS·HTML을 복사할 수 있고, 되돌리기·다시 실행, 프리셋 불러오기, URL로 상태 공유가 된다 |
| **속성 설명** | 속성 31개를 값별 데모로 하나씩 설명한다. 각 항목에 MDN 링크가 붙는다. 탭 끝에 Flex ↔ Grid 개념 대조 6쌍 |
| **실전 예제** | 네비게이션 바·카드 그리드·홀리 그레일 같은 실제 레이아웃 36건. 예제를 플레이그라운드로 가져와 이어서 고칠 수 있다 |
| **챌린지** | 목표 그림을 보고 속성을 맞히는 문제 80건. 힌트와 정답 보기가 있고, 푼 문제는 브라우저에 기록된다 |

토픽은 **Flex**와 **Grid** 둘이며, 헤더에서 전환합니다. 탭 구성은 두 토픽이 같습니다.

## 담고 있는 것

숫자는 전부 코드에서 센 값입니다.

| | Flex | Grid | 합 |
| --- | ---: | ---: | ---: |
| 조작 가능한 속성 | 12 | 19 | **31** |
| ├ 컨테이너 스코프 | 6 | 12 | 18 |
| └ 아이템 스코프 | 6 | 7 | 13 |
| 실전 예제 | 18 | 18 | **36** |
| 챌린지 | 40 | 40 | **80** |
| 프리셋 | 5 | 5 | **10** |

- 속성 31개 전부에 설명문·팁·MDN 링크·URL 직렬화 키가 있습니다.
- 챌린지 난이도는 ⭐ 32건 · ⭐⭐ 29건 · ⭐⭐⭐ 19건입니다.
- 예제는 레이아웃 · 정렬 · 반응형 · UI 컴포넌트 · 폼 다섯 갈래입니다.
- 프리뷰 아이템은 최대 20개까지 늘릴 수 있습니다.
- **조건 때문에 효과가 없는 속성 12건을 흐리게 표시**하고 그 이유를 문장으로 알려줍니다
  (선언 14개 — 한 속성의 여러 값에 걸리는 자리가 있습니다).

## 설계 — 스키마가 단일 진실 공급원

컨트롤 UI · 코드 생성 · 챌린지 정답 판정 · 속성 설명 데모 · URL 직렬화가
전부 `js/topics/*/schema.js` **한 곳에서 파생**됩니다.
속성을 하나 더 붙이는 일이 스키마 항목 하나를 더 쓰는 일로 끝납니다.
마크업에 버튼을 심거나 코어에 `if (prop === '...')` 를 더하지 않습니다.

그 구조가 실제로 값을 했는지는 이력으로 확인할 수 있습니다.

> `js/core/store.js`는 지금까지 **커밋 2건**에서만 바뀌었고, 마지막 변경은
> 2026-08-18의 `292ba69`입니다. 그 뒤로 **92개 커밋**이 쌓이는 동안 한 줄도
> 고치지 않았습니다. Grid 토픽 전체 — 토픽 전환 · 트랙 편집기 · 라인 좌표 편집기 ·
> 영역 이름 편집기 · 라인 번호 오버레이 · 암시적 트랙 구분 · text 컨트롤이
> 그 92개 안에 들어 있습니다. Grid 마일스톤에서 늘어난 1,298줄은 전부
> 스키마·컨트롤·편집기 쪽이고, 상태 저장소는 그대로였습니다.

컨트롤 타입은 7종입니다 — `enum` · `number` · `length` · `text` ·
`track-list` · `area-grid` · `span`. 새 타입이 필요하면 `CONTROL_TYPES`에 등록하고
`ui/controls.js`에 렌더러를 더합니다.

## 기술 스택

HTML · CSS · 바닐라 JavaScript. 그 밖에는 없습니다.

- **의존성 0.** npm 패키지도, CDN 스크립트도, 웹폰트도 쓰지 않습니다.
- **빌드 없음.** 트랜스파일도 번들링도 하지 않습니다. 소스가 곧 배포본입니다.
- **ES 모듈.** `<script type="module">` 하나로 시작하고 전역을 만들지 않습니다.
- **색은 전부 토큰.** `css/tokens.css` 밖에 색상 리터럴이 없습니다.
  primitive 위에 semantic 별칭을 얹은 2계층입니다.

규모는 JS 10,384줄 · CSS 2,678줄 · 검증 스크립트 8,485줄입니다.

## 로컬에서 실행

정적 파일이라 아무 정적 서버로나 열립니다.

```bash
python3 .claude/serve.py 7788
```

`http://localhost:7788` 로 접속합니다.
같은 Wi-Fi의 태블릿·폰에서는 `http://<맥의 IP>:7788` 로 열립니다.

## 검증 게이트

테스트 프레임워크를 쓰지 않습니다. `tools/` 아래 순수 Node 스크립트 **17종**이
스키마 계약 · 렌더러 · 코드 생성 · 각 편집기 · 예제 · 챌린지 · 접근성 구조를
확인합니다. 실패하면 종료 코드가 0이 아닙니다.

```bash
for f in tools/check-*.mjs tools/validate-*.mjs; do node "$f" || echo "FAIL $f"; done
```

스키마를 고쳤다면 최소한 이것은 통과해야 합니다.

```bash
node tools/validate-schema.mjs
```

## 품질 기준

PRD 6장의 11개 항목을 M6에서 전부 충족했습니다.

| 항목 | 실측 |
| --- | --- |
| 하드코딩 색상 | 0건 |
| 인라인 `style=` · `onclick=` | 0 · 0 |
| `!important` | 0건 |
| 참조되지 않는 코드 | 0줄 |
| 반응형 브레이크포인트 | 3구간 (경계 599/600 · 1023/1024) |
| 키보드 단독 조작 | 전 기능 가능 |
| Lighthouse 접근성 | 100 (6회 편차 0) |
| Lighthouse 성능 (모바일) | 중앙 100 · 최소 98 (6회) |
| 조건부 속성 비활성 표시 | 12/12 |

Lighthouse 수치는 배포 환경(GitHub Pages) 기준이며 기본 설정(모바일 · `simulate`)
6회 측정의 중앙값입니다. 자세한 조건은 PRD 6장에 적어 두었습니다.
